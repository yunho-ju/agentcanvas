# 지금 그래프에 어떤 모양이 빠져 있는가 — 신호의 케이스

`cases.json`은 엔진의 `detect_all`(packages/engine/agentcanvas_engine/patterns/detect.py)이
문서 하나를 보고 **무슨 신호를 내는지** 고정한다. 신호는 "이 모양을 넣으라"는 명령이 아니라
Improve가 근거로 읽는 관찰이다("이 에이전트는 도구를 한 번만 부르고 끝난다").

한 케이스의 뜻:

| 칸 | 뜻 |
|---|---|
| `nodes` | 문서에 놓인 노드들 — `id`·`type`·`config`만 적는다 (자리는 판정에 쓰이지 않는다) |
| `resources` | 문서가 든 연결들 — `id`와 승인 정책만 적는다 (없는 이름을 가리키는 노드는 도구를 못 쓴다) |
| `edges` | 값이 흐르는 방향 `[보내는 노드, 받는 노드]` — 포트 이름은 이 판정에 쓰이지 않는다 |
| `signals` | 그 문서에서 나오는 신호 전부 — 카탈로그 차례(react → human_gate → router) 그대로 |
| `strength` | `strong`은 문서에서 본 사실, `weak`은 정황뿐인 관찰(권하기 전에 사람에게 묻는다) |

한 케이스가 신호 여럿을 내는 것은 정상이다: 도구를 한 번만 부르는 에이전트는 동시에
사람 확인도 없고 갈림길도 없다. 신호가 **없다**고 적은 케이스가 무엇을 지키는지가 더 중요하다:

- 빈 문서는 아무 말도 하지 않는다.
- 부를 때마다 사람에게 묻는 연결(`ask_first`)은 이미 사람이 확인하는 것이다.
- 사람 확인이 그 노드의 **아래쪽**에 있을 때만 조용하다 — 아무 데도 이어지지 않은 확인 노드는
  누구의 길도 막지 못하므로 신호가 그대로 남는다.
- 문서에 없는 연결 이름을 가리키는 노드는 도구를 쓰지 못한다(빨간 줄은 검증기의 몫이다).

TS 미러는 아직 없다 (Improve 칩이 화면에 서는 단계에서 같은 파일을 읽는다).
