# 모양이 이 문서의 어느 단계에 놓이는가 — 앵커의 케이스

`cases.json`은 카탈로그의 템플릿이 가리키는 앵커(`{agent}`·`{input}`·`{output}`)가 이 문서의
**어느 노드가 되는지**, 또는 왜 될 수 없는지를 고정한다. 두 구현이 같은 답을 낸다:

- Python — 엔진의 `fill_template`(packages/engine/agentcanvas_engine/patterns/apply.py),
  서버가 초안에 모양을 합칠 때 쓰는 길.
- TS — 화면의 `resolveAnchors`(apps/studio/src/graph/patternAnchors.ts), 팔레트에서
  '이 모양으로 놓기'를 누를 때 쓰는 길.

**자리 정하기는 이 파일이 맞추지 않는다.** 새 노드가 앉을 좌표는 뷰포트를 아는 화면과 그것을
모르는 서버가 각자 정한다 (설계 문서 D12).

한 케이스의 뜻:

| 칸 | 뜻 |
|---|---|
| `pattern` | 카탈로그의 항목 id — 그 항목의 `template`을 이 문서에 채워 본다 |
| `nodes` | 문서에 놓인 노드들 — `id`·`type`·`config` (자리는 앵커 판정에 쓰이지 않는다) |
| `resources` | 문서가 든 연결들 — 없는 이름을 가리키는 노드는 도구를 쓰지 못한다 |
| `edges` | 값이 흐르는 방향 `[보내는 노드, 받는 노드]` |
| `selected` | 사람이 고른 노드 — 종류가 맞는 앵커만 이 노드가 된다 |
| `anchors` | 채워진 앵커 → 문서의 노드 id |
| `cannot` | 채울 수 없는 까닭 (`ambiguous_anchor`·`missing_node`·`needs_tools`·`no_tools_anywhere`) |

규칙은 하나다: 고른 노드가 그 종류면 그 노드, 아니면 그 종류가 문서에 정확히 하나일 때만,
여럿이면 애매하다고 말하고 지어내지 않는다. `requires_tools`가 붙은 앵커는 그 노드가 실제로
손이 닿는 연결을 하나도 들고 있지 않을 때, 문서에 도구가 붙은 연결이 **있으면** `needs_tools`
(고르기), **하나도 없으면** `no_tools_anywhere`(만들기)다 — 사람이 할 일이 다르므로 이름도
다르다. 그리고 **어느 노드인지가 먼저다**(고를 노드가 애매하면 도구를 묻기 전에 그것부터 말한다).

Python은 앵커 지도를 값으로 내놓지 않으므로, 채워진 patch 작업들이 **문서의 어느 노드를
건드렸는가**로 같은 답을 확인한다(작업이 새로 놓는 노드는 문서의 노드가 아니다).

## 이 파일이 맞추지 않는 것

- **포트 해석(`unknown_port`)**: 앵커 규칙이 아니라 registry의 일이라 두 쪽이 각자 제 registry에게
  묻는다.
- **`{new:...}` 앵커를 연결의 끝으로 쓰고 그 포트를 `*`로 적은 템플릿**: 여기서 두 구현은
  실제로 갈린다 — 엔진은 아직 문서에 없는 노드라며 거절하고(`missing_node`), 화면은 그 카드를
  먼저 놓은 뒤 그 카드의 첫 포트로 잇는다. 이 자리는 **미러 밖**이다(카탈로그의 세 템플릿은
  새 노드의 포트를 이름으로 적으므로 지금 이 갈림에 닿지 않는다). 어느 한쪽으로 맞추려면
  계약이 먼저 정해야 한다.
