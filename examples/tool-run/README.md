# 도구가 실제로 일하는 실행 — 예시 하나와 그 실행 기록

`agent_spec.json`은 도구 노드 하나가 든 가장 작은 그래프다: 물어볼 말을 받아
(`core.input`), 연결이 들고 있는 도구를 한 번 부르고(`tool.mcp`), 받은 것을 답으로
내보낸다(`core.output`). 도구가 어그러졌을 때 흐르는 갈래(`error` 포트)도 함께 그려
두었다 — 잘 끝난 실행에서는 그 갈래가 흐르지 않는다는 것도 기록이 말한다.

`run_events.json`은 그 그래프를 **결정론 대역**(`just_echoes` — 건넨 것을 그대로
되읊는 자리)으로 돌렸을 때 나오는 이벤트 전부다. 진짜 HTTP를 부르지 않으므로 언제
돌려도 같은 기록이 나온다. 파일은 대조 기준이므로 손으로 고쳐 쓰지 않는다 (실행기가
바뀌면 다시 만들어 diff를 본다 — `packages/engine/tests/test_routed_events_golden.py`).

이 기록이 못 박는 것:

- 도구 노드가 내는 세 사건의 모양 — `tool.policy_checked`(써도 되는가) →
  `tool.requested`(무엇을 건넸는가) → `tool.completed`(무엇을 받았고 얼마를 실었는가).
- 열쇠는 이름으로만 적힌다: 도구의 `auth`는 `secret://article-api-key`이고, 실값은
  서버를 띄운 자리에만 있다 (이벤트 어디에도 열쇠가 없다).
  **이 보장의 범위**: 서버가 관리하는 열쇠(`secret://` 이름 → Authorization 헤더)에
  한한다. 사람이 도구의 입력 값이나 주소(`url_template`)에 열쇠를 직접 박아 넣으면 그
  값은 실행 기록에 남는다 — 이름이 열쇠처럼 생기지 않은 자리는 계약 guard가 보지 못한다.
  열쇠는 언제나 `secret://` 이름으로 적는다.
- 크기를 두 값(`original_chars`/`loaded_chars`)으로 적는다 — 지금은 통째로 실으므로
  둘이 같다. 줄여 싣는 전략이 생겨도 화면과 계약은 이 자리를 그대로 읽는다.

아직 아닌 것: 연결의 `approval_policy`는 문서에 적히기만 하고 실행이 보지 않는다.
"사람이 확인해야 부를 수 있는 도구"는 다음 조각(P3b)에서 사람 확인 멈춤과 함께 붙는다.
